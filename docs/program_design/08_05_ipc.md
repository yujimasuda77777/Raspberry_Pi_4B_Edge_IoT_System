# 08_05 IPC設計

## 1. 目的

本書では、Sensor ProcessとCommunication Processの間でSensorDataを受け渡すためのIPC（プロセス間通信）を定義する。

本システムでは、POSIX Message Queueを使用する。

---

## 2. IPCの位置づけ

Sensor ProcessとCommunication Processは、それぞれ独立したプロセスとして動作する。

そのため、Sensor Processが作成したSensorDataをCommunication Processへ渡すための仕組みが必要になる。

本システムでは、Message Queueを使用してデータを受け渡す。

```text
Sensor Process
      │
      │ SensorData
      ▼
┌─────────────────┐
│ POSIX Message   │
│ Queue           │
└─────────────────┘
      │
      │ SensorData
      ▼
Communication Process
```

---

## 3. Message Queueの役割

Message Queueは、Sensor ProcessとCommunication Processの間にあるデータ受け渡し場所として使用する。

### Sensor Process

SensorDataをMessage Queueへ送信する。

### Communication Process

Message QueueからSensorDataを受信する。

したがって、基本的な関係は以下となる。

```text
Sensor Process
    ↓
Queueへ送信

Communication Process
    ↑
Queueから受信
```

---

## 4. Queue名

使用するMessage Queueの名前は以下とする。

```text
/raspberry_pi_edge_iot_sensor_data
```

Sensor ProcessとCommunication Processの両方で同じ名前を使用する。

---

## 5. Queueの容量

Message Queueの最大保持数は100とする。

```text
最大メッセージ数：100
```

Sensor Processがデータを送信し、Communication Processがすぐに受信できない場合でも、最大100件までQueueに保持できる。

イメージ：

```text
Sensor Process
      ↓
┌─────────────────────┐
│ 1                   │
│ 2                   │
│ 3                   │
│ ...                 │
│ 100                 │
└─────────────────────┘
      ↓
Communication Process
```

---

## 6. Queueに格納するデータ

Queueへ送信するデータは`SensorData`とする。

SensorDataには以下の情報が含まれる。

```text
temperature
humidity
timestamp
data_id
```

Queue上では、1つのSensorDataを1つのメッセージとして扱う。

```text
SensorData
    ↓
1メッセージ
```

---

## 7. Queueへの送信

Sensor Processは、SensorDataを生成した後にMessage Queueへ送信する。

処理順序は以下とする。

```text
DHT11読み取り
      ↓
SensorData生成
      ↓
data_id設定
      ↓
timestamp設定
      ↓
Message Queueへ送信
```

送信時点でSensorDataの必要な項目は設定済みとする。

---

## 8. Queueからの受信

Communication Processは、Message QueueからSensorDataを受信する。

基本的な処理は以下とする。

```text
Message Queue
      ↓
SensorData受信
      ↓
HTTP送信処理
```

Communication Processは、受信したSensorDataを使用してCloudflare Workerへデータを送信する。

---

## 9. Sensor Processの送信方式

Sensor ProcessからのQueue送信は、無期限に待ち続けない方式とする。

Queueに空きがない場合、送信処理は失敗として扱う。

基本的な処理は以下とする。

```text
SensorData
    ↓
Queue送信
    │
    ├─ 成功 → 次の周期
    │
    └─ 失敗 → ログ出力 → 次の周期
```

Sensor ProcessがQueueの空きを待ち続けることで、センサ処理そのものが停止することを避ける。

---

## 10. Communication Processの受信方式

Communication Processは、Queueにデータが届くまで待機する方式とする。

つまり、データがない場合は無理に処理を実行しない。

```text
Communication Process
        ↓
Queueから受信待ち
        ↓
SensorData受信
        ↓
通信処理
        ↓
次の受信待ち
```

この方式により、Communication Processは常にセンサデータを待ち受けることができる。

---

## 11. Queueのデータ順序

Message Queueでは、基本的に送信された順番でSensorDataを処理する。

例：

```text
送信

data_id = 1
data_id = 2
data_id = 3
data_id = 4

        ↓

受信

data_id = 1
data_id = 2
data_id = 3
data_id = 4
```

通常のセンサデータ処理では、この順序を維持する。

---

## 12. Queueが満杯になった場合

Queueに100件のメッセージが存在し、空きがない場合、Sensor Processからの送信は失敗する。

この場合、Sensor Processは現在のデータを無期限に待機して送信しようとはしない。

```text
Queue満杯
   ↓
送信失敗
   ↓
ログ出力
   ↓
次のセンサ周期へ
```

この場合、そのSensorDataはCommunication Processへ渡されない。

---

## 13. Queueから受信したデータの扱い

Communication ProcessがQueueからSensorDataを受信した後、そのSensorDataを通信処理へ渡す。

重要なのは、Queueから受信した時点でSensorDataの値を基本的に変更しないことである。

```text
Queueから受信
      ↓
SensorData
      ↓
CloudflareClient
      ↓
HTTP POST
```

温度、湿度、timestamp、data_idは、そのまま通信処理へ引き渡す。

---

## 14. data_idの扱い

`data_id`はSensor Processが生成する。

IPC処理では`data_id`を変更しない。

```text
Sensor Process
data_id = 10
      ↓
Message Queue
data_id = 10
      ↓
Communication Process
data_id = 10
```

さらにHTTP通信で再送する場合も、同じ`data_id`を使用する。

---

## 15. timestampの扱い

`timestamp`もSensor Processで設定する。

IPC処理では変更しない。

```text
Sensor Process
timestamp = 取得時刻
      ↓
Message Queue
timestamp = 取得時刻
      ↓
Communication Process
timestamp = 取得時刻
```

通信処理に時間がかかっても、センサ取得時刻そのものは変更しない。

---

## 16. IPCクラス

Message Queueの処理は、`SensorDataMessageQueue`クラスにまとめる。

対象ファイルは以下とする。

```text
include/
└── ipc/
    └── SensorDataMessageQueue.h

src/
└── ipc/
    └── SensorDataMessageQueue.cpp
```

---

## 17. SensorDataMessageQueueの責務

`SensorDataMessageQueue`は、POSIX Message Queueを直接扱うクラスとする。

主な責務：

* Queueのオープン
* Queueの送信
* Queueの受信
* Queueのクローズ
* Queue関連エラーの処理

Sensor ProcessやCommunication Processは、POSIX Message Queue APIの細かな処理を直接扱わない。

---

## 18. SensorDataMessageQueueとSensor Process

Sensor Processでは、`SensorDataMessageQueue`を使用してSensorDataを送信する。

```text
Sensor Process
      ↓
SensorDataMessageQueue
      ↓
POSIX Message Queue
```

Sensor Processは、

「POSIX Message Queueをどのようにオープンするか」

などの詳細を意識しない構成とする。

---

## 19. SensorDataMessageQueueとCommunication Process

Communication Processでは、同じ`SensorDataMessageQueue`を使用してSensorDataを受信する。

```text
POSIX Message Queue
      ↓
SensorDataMessageQueue
      ↓
Communication Process
```

これにより、IPCに関する処理を1つのクラスにまとめる。

---

## 20. Queueのオープン

Sensor ProcessとCommunication Processは、それぞれ起動時にQueueをオープンする。

```text
Sensor Process
      ↓
Queue Open
      ↓
送信可能

Communication Process
      ↓
Queue Open
      ↓
受信可能
```

両プロセスは同じQueue名を使用する。

---

## 21. Queueのクローズ

プロセス終了時には、使用していたMessage Queueのハンドルをクローズする。

```text
プロセス終了
      ↓
Queue Close
      ↓
プロセス終了
```

Queueそのものの寿命と、プロセスが保持するハンドルの寿命は分けて考える。

---

## 22. Queueの永続性

本システムのMessage Queueは、アプリケーションのデータベースとして使用するものではない。

Message Queueは、プロセス間でデータを受け渡すための一時的な通信手段として使用する。

そのため、プロセス停止・再起動時に未送信データを永久保存することは目的としない。

```text
Message Queue
    ↓
プロセス間の一時的なデータ受け渡し
```

データの永続保存はCloudflare D1側で行う。

---

## 23. Sensor Process停止時

Sensor Processが停止すると、新しいSensorDataはQueueへ送信されなくなる。

Communication ProcessはQueueに残っているデータがあれば、それを処理する。

Queueにデータがなくなった場合は、次のデータを待つ。

---

## 24. Communication Process停止時

Communication Processが停止した場合でも、Sensor Processは一定周期で動作を続ける。

Queueに空きがある間はSensorDataをQueueへ送信できる。

そのため、一時的なCommunication Process停止により、Sensor Processまで直ちに停止する構成にはしない。

ただし、Queueが満杯になった場合はSensor Process側の送信が失敗する。

---

## 25. IPC処理の全体フロー

```text
┌──────────────────────┐
│    Sensor Process    │
│                      │
│ DHT11から取得        │
│       ↓              │
│ SensorData生成       │
└──────────┬───────────┘
           │
           │ send
           ▼
┌──────────────────────┐
│   POSIX Message      │
│       Queue          │
│                      │
│ 最大100メッセージ    │
└──────────┬───────────┘
           │
           │ receive
           ▼
┌──────────────────────┐
│ Communication       │
│ Process              │
│                      │
│ SensorData受信       │
└──────────────────────┘
```

---

## 26. IPCで変更してはいけないデータ

Message Queueを通過する際、以下の値は変更しない。

```text
temperature
humidity
timestamp
data_id
```

IPCの役割はデータの加工ではなく、プロセス間の受け渡しである。

---

## 27. IPCエラーの基本方針

IPC処理でエラーが発生した場合は、エラー内容をログへ出力する。

ただし、IPCエラーだけを理由にプロセス全体を無条件に終了させない。

具体的なエラー処理については、

`08_08_error_retry.md`

でまとめて定義する。

---

## 28. 設計上のポイント

IPCでは以下を基本方針とする。

### 28.1 Sensor ProcessとCommunication Processを分離する

センサ取得とネットワーク通信を別プロセスとして扱う。

### 28.2 Message Queueはデータ受け渡しに限定する

Message Queue上でデータ加工や通信処理を行わない。

### 28.3 SensorDataをそのまま渡す

温度・湿度・timestamp・data_idを一つのデータとして渡す。

### 28.4 Sensor ProcessをQueue待ちで停止させない

Queue送信では無期限に待機しない。

### 28.5 Communication Processはデータを待つ

Communication ProcessはQueueからデータを受信するまで待機する。

## 31. まとめ

IPCでは、POSIX Message Queueを使用してSensor ProcessとCommunication Processの間でSensorDataを受け渡す。

基本的な流れは以下である。

```text
Sensor Process
      ↓
SensorData
      ↓
Message Queue
      ↓
Communication Process
```

Message Queueは一時的なデータ受け渡しに使用し、データの加工や永続保存は行わない。

また、`temperature`、`humidity`、`timestamp`、`data_id`はQueueを通過する間も維持する。
